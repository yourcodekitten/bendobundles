# The Doorstep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give an 81-day-stuck `Pending` claim a window an operator can look at and a hand an operator can press.

**Architecture:** Two new `FulfillRequest` verbs — `StuckClaims` (read) and `Compensate` (write) — invoked from `admin-api` through the existing `AdminInvoker`. `admin-api` gains two HTTP routes and `web/src/admin/Ops.tsx` gains a section with a two-step confirm button. `FulfillRequest` is **already the admin-ops channel**, not just the fulfillment channel: `Sync` is a variant and `admin-api` fires it from a human-pressed button (`crates/admin-api/src/lib.rs:1344`, `s.invoker.fire(FulfillRequest::Sync)`). These are members 2 and 3 of that pattern.

**The two verbs live in fulfillment for TWO DIFFERENT reasons, and one will not cover both** (Lilith, 2026-09-25 — she measured my first single-reason version false):

- **`StuckClaims` — because of the GRANT, and this is the load-bearing half.** `Store::list_pending_claims` is **one grant-tuple and `admin-api` holds zero of it**: `Query · index pending-claims · leading_keys [PENDINGCLAIM] · gsi2pk`. **A new GSI *and* a key prefix `admin-api` has never touched** — it queries exactly one index today (`listable`, via `list_friends`). A direct call is a real widening of its surface.
- **`Compensate` — because of a CORRECTNESS invariant, NOT IAM.** 🔴 **My earlier claim that this widens `admin-api`'s grant "for the claim state machine" is FALSE, and I stated it twice.** Both peers measured the write's delta as **small and mostly already held** — `admin-api` already uses `TransactWriteItems`, already writes `claims_used` on `LINK#` via `create_link`, and `claim_game_self`'s `UpdateItem` on `GAME#` carries compensate's entire `GAME#` attribute set. ***`admin-api` already moves claims — it creates them.***
  📏 **THE FIGURE, WITH ITS UNIT — because the 4× disagreement was two aggregations, not an error, and a count with no unit caused it.** Settled across both peers' seats: **per-REQUEST** `compensate_self_claim` **4**, `compensate_claim` **5**; **per-ATTRIBUTE** **16** and **19**; **self ⊂ claim strictly at both levels**, and the union is **19, not 35** — *a permission is not needed twice.* The entire difference is **one request** (`UpdateItem via TWI · LINK# · claims_used|pk|sk`) = **1 request / 3 attribute facts.**
  💰 **Which PRICES the scope decision below instead of leaving it a philosophy question: widening from self-only to both arms costs exactly that one request's worth of grant — and buys the friend arm.**

> 🧭 **SCOPE DECISION — STATED FIRST, BECAUSE THE REASON ABOVE DEPENDS ON IT** (OMBB, 2026-09-25: he caught me about to write down an invariant attached to the wrong verb). **The button compensates BOTH arms — self AND friend claims — dispatching through `compensate_any`.**
> **Why both, and it is the pounce's own thesis:** the window lists every stuck claim, and **a stuck FRIEND claim is the more urgent one — a real person is waiting.** A surface that displays a problem the button cannot act on ships *"nothing can fix it"* one layer up, which is the exact defect this work exists to remove.
> ⇒ **and only because the scope is BOTH does the double-spend reason apply:** `compensate_self_claim` **never touches `claims_used`** — its doc says *"NO link decrement — LINK#SELF has no META item"*, which is why the self variant exists at all. The decrement lives in `compensate_claim`. **So: two roles able to decrement `claims_used` is a double-spend surface if they race — true of the friend arm, and therefore true of this verb, and it would have been FALSE had the button been self-only** (which is how #236 reads on its face).

⚠️ **Task 6 therefore proves ONE thing, not two:** that the read's grant did not move. It is not evidence about the write.

🔬 **A CORPUS-READING CAVEAT, carried because this plan's whole argument leans on that file** (Lilith, 2026-09-25): `list_pending_claims`' corpus entry reads `attributes: ["gsi2pk"]` while the method returns **whole `Claim`s**. ⇒ ***For a Query, the corpus's `attributes` is the IAM CONDITION, not the projection.*** **You cannot infer what a method READS from it** — only what the policy gates on. Harmless here; it would mislead the moment someone sizes a payload or a blast radius from that field.

✅ **And the seam between the two verbs was checked and does not exist:** `list_pending_claims` returns `Vec<Claim>`, so each window row already carries `claim_id` **and** `link_token`. The button constructs `Compensate { claim_id, link_token }` from data it already has — **no second read at the call site.**

**Tech Stack:** Rust (axum, tokio, serde, `time`), DynamoDB via `crates/dynamo`, React + TypeScript + Vitest in `web/`.

**Spec:** `docs/spec-doorstep.md`

## Global Constraints

- The stale bar is **`RECONCILE_STUCK_ALERT_AGE`** = `time::Duration::hours(24)` (`crates/fulfillment/src/lib.rs:114`). Do not introduce a second constant.
- `SELF_LINK_TOKEN` = `"SELF"` (`crates/domain/src/lib.rs:448`). A self-claim is `claim.link_token == domain::SELF_LINK_TOKEN`.
- `Claim` fields used here: `id: String`, `link_token: String`, `game_id: String`, `state: ClaimState`, `created_at: OffsetDateTime` (`crates/domain/src/lib.rs:300`).
- `ClaimState::{Pending, Fulfilled, Compensated, Failed}` (`crates/domain/src/lib.rs:33`).
- **No new IAM.** If any task requires a DynamoDB action/condition `admin-api` does not already hold, stop and escalate — the architecture is wrong, not the policy.
- **Never auto-compensate.** No timer, no sweep-triggered write. Every compensate is a human press.
- 🔴 **DEPLOY FULFILLMENT BEFORE ADMIN-API.** `FulfillRequest` is `#[serde(tag = "op", rename_all = "snake_case")]` (`crates/fulfillment/src/lib.rs:117`) with **zero `serde(other)`** across the variant span, so a `stuck_claims` or `compensate` payload reaching an **old** fulfillment lambda is a hard deserialize failure surfaced to the operator as a string from a button press. Two new variants doubles that window.
  ⚠️ **The repo's own forward-compat habit stops exactly one level short of this case** (Lilith): `Gift.requires_choice` is `#[serde(default)]` with a comment saying it keeps existing payloads wire-valid — **that makes a new FIELD safe. A new VARIANT has no default.** Do not reach for that precedent here.

```rust
// in FulfillRequest (crates/fulfillment/src/lib.rs:118)
    /// Operator read: every Pending claim past `RECONCILE_STUCK_ALERT_AGE`. Read-only; no writes,
    /// no pings. Lives here and not in admin-api because `list_pending_claims` is granted to the
    /// fulfillment role alone (terraform/iam-request-corpus.json).
    StuckClaims,

#[derive(Debug, Clone, serde::Serialize, serde::Deserialize, PartialEq)]
pub struct StuckClaim {
    pub claim_id: String,
    pub game_id: String,
    pub link_token: String,
    pub is_self: bool,
    pub pending_since: OffsetDateTime,
    pub age_hours: i64,
}

// in the dispatch match
FulfillRequest::StuckClaims => {
    let now = OffsetDateTime::now_utc();
    let mut rows: Vec<StuckClaim> = deps
        .store
        .list_pending_claims()
        .await?
        .into_iter()
        .filter(|c| c.state == ClaimState::Pending && now - c.created_at >= RECONCILE_STUCK_ALERT_AGE)
        .map(|c| StuckClaim {
            is_self: c.link_token == domain::SELF_LINK_TOKEN,
            age_hours: (now - c.created_at).whole_hours(),
            claim_id: c.id,
            game_id: c.game_id,
            link_token: c.link_token,
            pending_since: c.created_at,
        })
        .collect();
    rows.sort_by_key(|r| r.pending_since);
    Ok(FulfillResponse::StuckClaims(rows))
}
```

```rust
#[derive(serde::Deserialize)]
struct CompensateBody {
    link_token: String,
    /// Absent reads `false`: a destructive op must be asked for twice, and a client that forgets
    /// the field gets a 400 rather than a write.
    #[serde(default)]
    confirm: bool,
}

async fn handle_compensate(
    State(s): State<AppState>,
    session: Session,
    Path(claim_id): Path<String>,
    Json(body): Json<CompensateBody>,
) -> impl IntoResponse {
    let _ = session;
    if !body.confirm {
        return (StatusCode::BAD_REQUEST, "confirm required").into_response();
    }
    let req = FulfillRequest::Compensate { claim_id, link_token: body.link_token };
    match s.invoker.invoke_blocking(&req).await {
        Ok(FulfillResponse::Compensated) => StatusCode::NO_CONTENT.into_response(),
        Ok(other) => { tracing::error!(outcome = "compensate_wrong_variant", got = ?other); StatusCode::BAD_GATEWAY.into_response() }
        Err(e) => { tracing::error!(outcome = "compensate_invoke_failed", error = %e); StatusCode::BAD_GATEWAY.into_response() }
    }
}
```
