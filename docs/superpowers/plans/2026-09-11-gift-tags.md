# The Gift Tags ✍️ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-game gift tags on curated links — ben writes an optional "why i picked this one
for you" on each curated pick; the friend sees it on the card marker and in the detail modal
(the claim-ceremony placement was REJECTED by family review — spec D6; do not add it).

**Architecture:** `curated_notes: Option<BTreeMap<String,String>>` on `domain::Link`, stored
as a **top-level DynamoDB attribute on `curated_game_ids`' exact contract** — stripped from
the body blob, written once at create, read by unconditional override, **no update expression
ever names it** (claim-path and rollback erasure impossible by construction — the family-review
blocker that killed draft v1's body storage). It flows create-time-only through admin-api
validation, is overlaid onto the friend wire's `GameView` at the curated assembly sites (grid
partition + ghost) and the link-scoped detail endpoint, and renders on two presence-gated
friend surfaces (card marker + detail modal; the ClaimDialog ceremony was CUT from v1 by
family review — zero specimens to judge density from). Open-shelf payloads stay byte-identical;
sealed links withhold by construction (`games: []`).

**Tech Stack:** Rust (axum lambdas: domain / admin-api / public-api crates, dynamodb-local
tests via `store_or_skip`) · React + TypeScript (vite, vitest + testing-library).

**Spec:** `docs/spec-gift-tags.md` (same branch — the plan argues from it; executors read both).

## Global Constraints

- Validation failures in admin-api are **422** with a message naming the offending id (house
  convention — see `api_test.rs` "422 naming it" tests), not 400. (Spec D2 says 400; 422 is
  correct — the spec is amended by this line.)
- `GAME_NOTE_MAX_CHARS = 280` (chars via `.chars().count()`, same as `GIFT_NOTE_MAX_CHARS`).
- Notes are ben's words as typed — never lowercased, never trimmed beyond whitespace ends.
- Empty-after-trim notes are dropped, not stored; an empty map stores as `None`, never
  `Some(empty)`.
- Every friend render is presence-gated: no note ⇒ zero DOM, no layout ghosts (spec inv. 4).
- The Lowercase Rule / Pixel Grammar Rule / One Heart Rule / Ceremony Rule (DESIGN.md) govern
  all new UI copy and styling: our copy lowercase, prose in Chivo, no new ♡, no new shadows.
- All commits GPG-signed (`git commit -S`), branch `kitten/gift-tags`.
- **Export `DYNAMODB_LOCAL_URL=http://localhost:8000` before EVERY `cargo test`** (put it in
  the command line: `DYNAMODB_LOCAL_URL=http://localhost:8000 cargo test -p …`). With the env
  SET, `store_or_skip` PANICS if dynamodb-local is unreachable — *"refusing to skip (this
  would forge a green run)"* — and a panic cannot be captured away. With it UNSET the harness
  silently skips and `cargo test` hides the SKIP line for passing tests, so the run prints
  `ok` having verified nothing (OMBB's sign-off condition, 2026-09-11: the fail-loud mode
  existed in the harness and the plan didn't arm it). On THIS box there is no docker/java —
  the house recipe (decisions.md, 2026-07-06 parallel-agent hazards) is **moto on a PRIVATE
  port** (siblings collide on :8000 with identical table names): start
  `~/.local/bin/moto_server -p 8831 &` and export `DYNAMODB_LOCAL_URL=http://localhost:8831`
  on every cargo test line. CI runs the real dynamodb-local service; moto is the local stand-in.

```rust
const GAME_NOTE_MAX_CHARS: usize = 280; // a sticker, not a letter — gift_note (500) is the card

// in CreateLinkBody:
    #[serde(default)]
    game_notes: Option<std::collections::BTreeMap<String, String>>,

// in validate(), after the existing game_ids checks:
    if let Some(notes) = &self.game_notes {
        let Some(ids) = &self.game_ids else {
            return Err("game_notes requires game_ids (notes only exist on curated links)".into());
        };
        for (id, note) in notes {
            if !ids.contains(id) {
                return Err(format!("game_notes[\"{id}\"] has no matching game_ids entry"));
            }
            if note.trim().chars().count() > GAME_NOTE_MAX_CHARS {
                return Err(format!(
                    "game_notes[\"{id}\"] must be at most {GAME_NOTE_MAX_CHARS} characters"
                ));
            }
        }
    }

// in the create handler's Link construction (beside curated_game_ids: body.game_ids.clone()):
    curated_notes: body.game_notes.as_ref().and_then(|m| {
        let kept: std::collections::BTreeMap<_, _> = m
            .iter()
            .filter(|(_, v)| !v.trim().is_empty())
            .map(|(k, v)| (k.clone(), v.trim().to_string()))
            .collect();
        (!kept.is_empty()).then_some(kept)
    }),
```
